# M2Y 设计稿与 PRD 差距及修改方案

> 审查对象：[Page 1.svg](C:/Users/22798/Downloads/Page%201.svg)  
> 需求基线：[M2Y 产品需求文档 V1.1](./M2Y_PRD_修订版.md)  
> 审查日期：2026-08-13  
> 审查范围：PRD 的 P0/MVP 功能、核心流程、信息架构、状态规则、安全提示、离线同步和发布验收要求  
> 不在本次强制整改范围：PRD 明确归入 P1/P2 的诱饵界面、多设备同时在线、完整月历、实时协同、独立文件空间等能力

## 1. 结论

当前设计稿的产品方向与一级信息架构基本符合 PRD，已经覆盖：

- 启动、应用解锁、恢复码、配对/安全号码和欢迎引导；
- Chat、Space、设置三项一级导航；
- Chat 中的 Shared Item 卡片和讨论上下文；
- Space Home 的“需要你、接下来、置顶、最近更新”和类型筛选；
- Activity、时间视图、统一搜索；
- “保存到 Space”动作面板；
- Agreement 详情、确认、等待对方和删除确认等部分流程。

但是，当前设计稿**尚不能通过 PRD P0/MVP 验收**。主要原因是：

1. Chat 的 P0 消息类型、发送状态、撤回和焚毁模式未覆盖；
2. 收藏、待办、笔记、文件四类 Shared Item 没有形成详情与状态闭环；
3. Agreement 只覆盖部分确认流程，缺少请求修改、重新确认和历史版本；
4. 注册、三种配对方式、设备换机/撤销、解绑数据处理未完整设计；
5. 离线、同步、冲突、失败和恢复等关键状态缺失；
6. 部分文案与 PRD 的安全边界或删除规则冲突；
7. 静态界面没有配套状态说明，无法证明加密、同步、通知隐私和数据清理等非视觉需求。

因此建议将当前稿定位为：

> **M0 核心概念与 Agreement 流程原型，而不是可直接进入 P0/MVP 开发验收的完整设计稿。**

---

## 2. 优先级定义

| 优先级 | 定义 | 处理要求 |
|---|---|---|
| P0-阻断 | 缺失会导致 PRD 核心闭环无法完成或产生安全/状态错误 | 开发前必须补齐 |
| P0-重要 | 不阻断最短主路径，但属于 MVP 明确能力或发布验收条件 | MVP 设计冻结前补齐 |
| P0-规范 | 视觉稿无法单独证明，需要补充状态表、交互说明或验证材料 | 交付开发前补齐 |

---

## 3. 不满足项与修改方案

### 3.1 首次使用、身份与配对

PRD 依据：3.1、6.1、7.1、12.1、12.4。

#### ID-01 缺少本地身份创建与 M2Y-ID 生成结果

- **优先级**：P0-阻断
- **现状**：设计稿从启动/解锁直接进入配对或欢迎流程，没有明确展示首次启动时在设备端创建身份、生成随机 M2Y-ID 的过程与结果。
- **PRD 要求**：无需手机号或邮箱，在设备端生成身份密钥和随机 M2Y-ID。
- **修改方案**：
  1. 在首次启动与配对之间增加“创建本地身份”页；
  2. 展示生成中的安全说明，完成后显示 M2Y-ID；
  3. 提供“复制 M2Y-ID”和“继续设置恢复方式”；
  4. 明确说明无需手机号、邮箱或通讯录；
  5. 不展示私钥、原始密钥材料或误导性的“平台可帮你找回”文案。
- **验收条件**：用户可从全新安装状态看懂身份由本机创建，并获得可用于配对的 M2Y-ID。

#### ID-02 缺少可选显示名和头像设置

- **优先级**：P0-重要
- **现状**：配对后直接使用“我/TA”，未展示显示名和头像的可选设置。
- **修改方案**：增加轻量“你希望 TA 如何看到你”步骤，显示名与头像均可跳过，并标注“只对你和配对对象可见”。
- **验收条件**：跳过不阻断配对；填写后能预览在 Chat 中的展示效果。

#### ID-03 只有解锁页，没有首次设置应用锁的流程

- **优先级**：P0-阻断
- **现状**：已有 Face ID/指纹/PIN 解锁页，但没有 PIN 创建、确认、生物识别授权拒绝和降级流程。
- **修改方案**：补充以下状态稿：
  - 创建 PIN；
  - 再次确认 PIN；
  - 请求启用生物识别；
  - 用户拒绝权限后使用 PIN；
  - 生物识别失败、锁定或系统不可用；
  - 忘记 PIN 后进入恢复流程。
- **验收条件**：所有情况下都存在明确、安全且不泄露内容的下一步。

#### ID-04 恢复码页面出现得过晚，缺少确认保存步骤

- **优先级**：P0-阻断
- **现状**：有恢复码展示页，但没有证明用户已安全保存，也没有明确“平台无法替你恢复历史内容”的不可逆风险。
- **修改方案**：
  1. 将恢复码放入首次身份建立流程；
  2. 增加“复制”“保存到系统密码管理器/安全位置”“我已手抄保存”；
  3. 点击继续前进行二次确认或抽查部分助记词；
  4. 增加丢失全部设备和恢复材料后的结果说明；
  5. 截图限制文案需区分 iOS 与 Android 能力，不承诺绝对禁止截图。
- **验收条件**：用户跳出该页前明确知道恢复材料的重要性和平台无法代恢复的边界。

#### ID-05 配对方式不完整

- **优先级**：P0-阻断
- **现状**：当前配对页主要提供扫码和 M2Y-ID 输入，缺少 PRD 要求的 10 分钟一次性握手码。
- **修改方案**：先增加“选择配对方式”页，再分别设计：
  - 扫描二维码；
  - 输入 M2Y-ID；
  - 输入一次性握手码；
  - 分享自己的 M2Y-ID/握手码；
  - 相机权限拒绝后的手动输入替代路径。
- **验收条件**：三种方式均能独立走到双方确认安全号码。

#### ID-06 缺少配对请求的双方确认、拒绝、取消和过期状态

- **优先级**：P0-阻断
- **现状**：配对页面直接以“确认配对”结束，没有展示发起方等待、接收方确认、拒绝、取消、网络失败和握手码过期。
- **修改方案**：新增配对请求状态组：
  - 发起请求；
  - 等待 TA 确认；
  - TA 收到请求并核对截断 ID；
  - 接受/拒绝；
  - 发起方取消；
  - 请求过期；
  - 请求失败及重试；
  - 已存在另一段关系时的阻断提示。
- **验收条件**：任何一方都不能在未经明确确认的情况下完成配对。

#### ID-07 安全号码核验语义不够明确

- **优先级**：P0-阻断
- **现状**：页面展示安全号码和“确认配对”，但未明确要求双方通过可信通道核对一致，也缺少“不一致”的处理入口。
- **修改方案**：
  - 使用“双方读到的号码是否完全一致？”作为主问题；
  - 主按钮改为“号码一致，确认配对”；
  - 增加“号码不一致”次要入口；
  - 不一致时停止配对并说明可能存在设备或密钥替换；
  - 增加复制安全号码和全屏二维码比对方式。
- **验收条件**：安全号码不一致时不能继续建立关系。

#### ID-08 缺少安全号码变化与密钥重建提示

- **优先级**：P0-阻断
- **现状**：只有首次安全号码展示，没有关系建立后号码变化的高可见提示。
- **修改方案**：增加 Chat 顶部安全横幅和独立详情页，覆盖：新设备、换机、密钥重建、安全号码变化；要求双方重新核验，核验前使用清晰但不过度恐吓的风险状态。
- **验收条件**：号码变化不能只记录在设置深层页面，双方进入 Chat 时均可见。

#### ID-09 缺少受控换机和设备撤销流程

- **优先级**：P0-阻断
- **现状**：设置中只有“设备管理”入口，没有设备列表和具体操作。
- **修改方案**：设计：
  - 当前活跃设备信息；
  - 新设备扫码/由已授权设备确认；
  - 原设备不可用时使用恢复材料；
  - 移除设备二次确认；
  - 移除后停止接收新密文的说明；
  - 无法保证擦除已离线复制内容的限制说明。
- **验收条件**：换机或移除设备的影响范围清晰，且不会暗示能远程必然擦除旧明文。

#### ID-10 解绑流程缺少本地数据处理选择

- **优先级**：P0-阻断
- **现状**：设置仅显示“解绑伴侣”，没有后续流程。
- **修改方案**：解绑确认页必须让发起方选择：
  - 删除本机数据；
  - 保留只读副本；
  并分别说明对本机、对方设备、未投递密文、服务端路由和已导出/截图内容的影响。
- **验收条件**：用户确认前能清楚区分“解绑”“本地删除”“共享对象删除”和“账户删除”。

### 3.2 Chat 消息与会话

PRD 依据：3.2、5.2、7.1、12.1、12.4。

#### CHAT-01 消息类型覆盖不完整

- **优先级**：P0-阻断
- **现状**：设计稿只明确展示文本消息和约定卡片。
- **缺少**：图片、文件、引用回复、系统事件。
- **修改方案**：为每种类型补充正常态及关键边界态：
  - 图片：缩略图、原图标识、加载、失败、全屏查看；
  - 文件：文件名、大小、上传进度、失败重试、打开失败；
  - 引用：被引用消息摘要、点击跳转、原消息不可用；
  - 系统事件：Item 创建、Waiting、完成、约定确认，视觉上区别于用户消息。
- **验收条件**：四类消息在 Chat 中可清晰区分，且不把系统事件伪装成用户消息。

#### CHAT-02 缺少发送状态与失败恢复

- **优先级**：P0-阻断
- **现状**：消息没有发送中、已送达或失败状态。
- **修改方案**：在自己发送的消息下方提供图标+文字状态；失败时提供“重试”和“删除本地草稿”，文件消息同时展示进度和失败原因类别。
- **验收条件**：状态不能只靠颜色；离线与发送失败必须可区分。

#### CHAT-03 缺少撤回流程及限制说明

- **优先级**：P0-重要
- **现状**：没有消息更多菜单、撤回确认及撤回后的占位状态。
- **修改方案**：增加长按菜单中的“撤回”；撤回后双方显示系统占位“你/TA 撤回了一条消息”；首次撤回时提示不能删除对方已截图、导出或复制的内容。
- **验收条件**：撤回后的引用和来源入口显示“原内容不可用”，但已显式保存的 Shared Item 按 PRD 保留。

#### CHAT-04 缺少“提醒我”本地动作

- **优先级**：P0-重要
- **现状**：长按消息后的本地提醒入口未设计。
- **修改方案**：在消息菜单中增加“提醒我”，明确“仅自己可见，不会保存到 Space”，补充选择时间、提醒已设置和取消提醒状态。
- **验收条件**：不会把本地提醒误显示给对方，也不会创建 Shared Item。

#### CHAT-05 缺少常规/阅后即焚模式

- **优先级**：P0-阻断
- **现状**：Chat 顶部没有模式切换，消息也没有倒计时和销毁状态。
- **修改方案**：
  1. 增加克制但明显的模式入口；
  2. 切换前说明只影响之后的新消息；
  3. 双方 Chat 中插入模式变化系统事件；
  4. 焚毁消息显示销毁起点、时长和剩余状态；
  5. 焚毁消息长按菜单不显示收藏、待办、笔记、约定或保存到 Space；
  6. 增加截图/录屏平台能力限制说明。
- **验收条件**：用户不会误以为焚毁模式能阻止外部相机拍摄或保证远程绝对擦除。

#### CHAT-06 缺少长按与多选消息状态

- **优先级**：P0-阻断
- **现状**：“保存到 Space”底部面板存在，但没有触发它的长按菜单、多选工具栏及连续/非连续选择状态。
- **修改方案**：补充：
  - 单条消息长按菜单；
  - 进入多选模式；
  - 已选数量；
  - 连续和非连续消息选择；
  - 混入焚毁消息时的禁止提示；
  - 取消选择与返回行为。
- **验收条件**：单条或多条常规消息均能在 3 次操作内进入任一支持的保存类型。

#### CHAT-07 在线状态缺少隐私控制语义

- **优先级**：P0-重要
- **现状**：Chat 头部直接展示“在线”，但设计稿未提供关闭在线/输入状态的设置。
- **修改方案**：将状态展示与“隐私与通知”设置关联，补充关闭状态；关闭后显示中性安全状态或不展示在线信息。
- **验收条件**：在线状态不是强制公开，也不会制造持续的关系压力。

### 3.3 Save to Space 核心动作

PRD 依据：3.3、6.2–6.5、7.1、12.1。

#### SAVE-01 缺少多选消息的来源预览

- **优先级**：P0-阻断
- **现状**：保存面板只显示一个标题输入框，看不到所选消息、发送者、时间和顺序。
- **修改方案**：在面板上方增加折叠式“已选择 N 条消息”来源预览，按聊天原顺序显示发送者、时间和摘要；允许返回调整选择。
- **验收条件**：保存前能确认多条消息的顺序与语境，保存后来源快照保持一致。

#### SAVE-02 四种保存类型缺少各自的默认填充和确认表单

- **优先级**：P0-阻断
- **现状**：四种类型共用单一标题字段，无法表达 PRD 中不同默认填充规则。
- **修改方案**：选择类型后切换为对应轻量表单：
  - 收藏：摘要/标题；
  - 待办：标题、说明、负责人、日期；
  - 笔记：可编辑草稿并保留消息顺序；
  - 约定：可编辑草稿，保存后仍处于 Draft，不直接确认。
- **验收条件**：每种类型的默认填充与 PRD 3.3.3 一致。

#### SAVE-03 文件自动索引规则没有体现

- **优先级**：P0-阻断
- **现状**：设计稿没有文件消息，因此无法看出文件发送成功后会自动进入 Space 文件筛选，也无法确认不会重复上传。
- **修改方案**：补充文件发送成功后的 Chat 卡片、Space 文件列表结果和“已自动收录到 Space”轻提示；文件的更多菜单可提供“关联到待办/笔记/约定”，但不再要求重新上传。
- **验收条件**：Chat 与 Space 明确引用同一文件资产。

#### SAVE-04 缺少保存结果与原始聊天双向跳转

- **优先级**：P0-阻断
- **现状**：Chat 有 Item 卡片和讨论上下文，但 Item 详情没有“查看原始聊天”和“相关聊天”的完整路径。
- **修改方案**：
  - 保存完成后在 Chat 插入轻量卡片或系统事件；
  - Item 详情增加“查看原始聊天”；
  - 点击后定位并高亮最早来源及关联消息；
  - 返回键回到 Item；
  - 从来源消息打开 Item 后，返回键回到原聊天位置。
- **验收条件**：路径与 PRD 5.3 导航规则一致。

#### SAVE-05 缺少来源消息撤回后的状态

- **优先级**：P0-重要
- **现状**：没有“来源已不可用”的设计。
- **修改方案**：Item 保留显式保存内容，但来源区域显示“原始消息已撤回/不可用”；入口禁用并说明原因。
- **验收条件**：不会因来源撤回而静默删除已共同保存的 Item。

### 3.4 Space Home

PRD 依据：3.4、5.4、7.1、12.1。

#### SPACE-01 “需要你”只展示 Agreement 示例，覆盖不足

- **优先级**：P0-重要
- **现状**：当前主要示例是“TA 等你确认约定”，没有覆盖指派给我的待办和正在等我的待办。
- **修改方案**：至少提供三个状态变体：
  - 指派给我的 Open/Doing 待办；
  - Waiting 且 waitingFor=当前用户；
  - 待当前用户确认的 Agreement。
- **验收条件**：完成、归档或只等待对方的内容不会进入当前用户“需要你”。

#### SPACE-02 类型筛选只有标签，没有各类型结果态

- **优先级**：P0-阻断
- **现状**：有“全部/收藏/待办/笔记/文件/约定”，但未展示切换后的列表、筛选保留和空结果。
- **修改方案**：为六个筛选状态给出内容样例；强调同一列表仅改变过滤条件，不改变一级导航；会话内保留筛选，重新进入 Space 回到首页。
- **验收条件**：不会被实现为五套独立工具页或五个嵌套 Tab。

#### SPACE-03 缺少分区空状态

- **优先级**：P0-重要
- **现状**：没有“需要你/接下来/置顶/最近更新”为空时的页面状态。
- **修改方案**：为每个分区定义是否隐藏或展示空状态；Space 整体为空时使用明确动作：“长按一条消息，保存到 Space”，并提供回到 Chat 按钮。
- **验收条件**：空状态给出具体下一步，而不是只显示“暂无内容”。

#### SPACE-04 Waiting 标签出现裁切

- **优先级**：P0-重要
- **现状**：“Waiting”标签在卡片右侧被裁切，且使用英文，与中文状态体系不统一。
- **修改方案**：改为完整中文状态，如“正在等你”或“待你确认”；预留动态字体宽度，必要时独占第二行。
- **验收条件**：390px 宽和系统大字体下均不截断，状态同时使用文字和图标表达。

#### SPACE-05 “接下来”与时间视图缺少“稍后”分组

- **优先级**：P0-重要
- **现状**：已有今天、未来 7 天和已超期，但没有 PRD 要求的“稍后”。
- **修改方案**：时间视图统一为“今天、未来 7 天、稍后、已超期”，并明确仅展示带日期的活跃待办和约定。
- **验收条件**：点击任一时间项进入原 Shared Item，而非创建独立日历对象。

### 3.5 Shared Item 通用能力

PRD 依据：3.5、4.2–4.5、5.2、12.1–12.3。

#### ITEM-01 通用详情仅在 Agreement 中体现

- **优先级**：P0-阻断
- **现状**：缺少统一的来源、相关聊天、生命周期和通用操作规范。
- **修改方案**：为所有 Item 详情定义统一骨架：
  - 类型、标题、创建者、创建/更新时间；
  - 来源消息快照；
  - 查看原始聊天；
  - 相关聊天；
  - 置顶/取消置顶；
  - 归档/恢复；
  - 删除；
  - 在聊天中讨论。
- **验收条件**：各类型只替换专属内容与状态，不复制出不同的导航规则。

#### ITEM-02 缺少归档、恢复和撤销删除状态

- **优先级**：P0-阻断
- **现状**：有归档按钮和删除弹窗，但没有归档列表、恢复流程或删除后的短暂撤销窗口。
- **修改方案**：
  - 增加归档完成 Toast 与“撤销”；
  - 增加归档筛选/入口和恢复动作；
  - 删除完成后提供短暂撤销；
  - 撤销期结束后再按策略清理。
- **验收条件**：与 PRD 4.2 的 Deleted 生命周期一致。

#### ITEM-03 删除弹窗描述过于绝对且影响范围不完整

- **优先级**：P0-阻断
- **现状**：文案写“从你们双方的 Space 中永久移除，且无法恢复”，没有区分撤销窗口、来源聊天、关联项、文件资产和离线副本。
- **修改方案**：按对象类型显示影响摘要；普通 Item 使用“删除共享项”，文件使用“删除文件资产”；列出 Chat、Space、关联项和对方设备上的影响，并注明已导出、截图或离线复制内容无法保证删除。
- **验收条件**：所有不可逆操作在确认前说明实际影响和能力边界。

#### ITEM-04 收藏与置顶仍需强化区分

- **优先级**：P0-重要
- **现状**：设计稿同时存在“收藏”类型和“置顶”动作，但缺少首次解释，容易理解为同一概念。
- **修改方案**：收藏面板文案改为“保存为收藏”；详情动作使用“置顶到 Space 首页”；首次使用提供一句说明：“收藏是一种内容类型，置顶是排序方式”。
- **验收条件**：可对任意类型置顶，且收藏 Item 也可置顶。

### 3.6 收藏（Pin Item）

PRD 依据：3.6、7.1、12.1。

#### PIN-01 缺少收藏详情与转换流程

- **优先级**：P0-阻断
- **现状**：只在保存面板和筛选标签中出现“收藏”，没有收藏结果页。
- **修改方案**：增加收藏详情/列表卡片，展示内容预览、发送者、保存者、来源时间和来源消息；提供转为待办、笔记或约定，并让用户选择转换后保留或归档收藏。
- **验收条件**：收藏可置顶、搜索、归档、删除和跳回来源。

### 3.7 待办（Task）

PRD 依据：3.7、6.2、6.6、7.1、12.1–12.2。

#### TASK-01 缺少待办创建和详情页

- **优先级**：P0-阻断
- **现状**：Space 有待办筛选和示例名称，但没有待办详情。
- **修改方案**：增加待办表单与详情：标题、说明、来源、负责人、状态、日期、提醒、讨论入口。
- **验收条件**：负责人只能是未指派、我、对方或双方，不出现团队、子任务、项目和复杂标签。

#### TASK-02 缺少 Open/Doing/Waiting/Done 状态流

- **优先级**：P0-阻断
- **修改方案**：设计状态菜单和状态变化后的卡片、Activity 与 Chat 系统事件；允许按实际情况前后切换；Done 后可重新打开。
- **验收条件**：创建并指派、进入 Waiting、完成、重新打开会回流 Chat；普通编辑只进入 Activity。

#### TASK-03 Waiting 没有选择正在等谁

- **优先级**：P0-阻断
- **现状**：只有 Space Home 的 Waiting 标签，没有设置 Waiting 的操作。
- **修改方案**：进入 Waiting 时弹出“正在等我/TA/双方”选择，并可填写一句“在等什么”；对方视角补充“正在等你”卡片。
- **验收条件**：只有被等待的一方在“需要你”中看到该项。

#### TASK-04 缺少本地提醒状态

- **优先级**：P0-重要
- **修改方案**：补充提醒时间选择、通知权限拒绝、提醒已设置、设备本地提醒说明和取消提醒状态。
- **验收条件**：不承诺绕过系统勿扰；不把提醒明文默认发到推送服务。

### 3.8 笔记（Note）

PRD 依据：3.8、4.5、7.1、12.1–12.3。

#### NOTE-01 缺少轻量富文本编辑页

- **优先级**：P0-阻断
- **现状**：只有笔记名称示例，无编辑体验。
- **修改方案**：增加标题、段落、列表、清单、加粗和链接的轻量编辑器；支持插入消息引用、图片和已有文件引用；不要设计成 Notion 式数据库或复杂 Markdown 工作台。
- **验收条件**：支持自动保存和 Chat 笔记卡片/讨论入口。

#### NOTE-02 缺少自动保存与同步状态

- **优先级**：P0-阻断
- **修改方案**：编辑页标题栏显示“正在保存/已保存/等待同步/同步失败”，失败时可重试；状态必须有文字而非只用颜色。
- **验收条件**：离线编辑不会被误认为已同步给对方。

#### NOTE-03 缺少并发冲突与版本恢复

- **优先级**：P0-阻断
- **修改方案**：增加“检测到两个版本”冲突页，完整保留双方文本，允许选择版本或手动合并；增加有限的最近版本恢复入口，不做任意版本树或复杂 Diff 工具。
- **验收条件**：任何情况下不得静默以最后写入覆盖另一方内容。

### 3.9 文件（File）

PRD 依据：3.9、6.5、7.1、12.1–12.2。

#### FILE-01 缺少文件列表与详情

- **优先级**：P0-阻断
- **现状**：搜索有“文件”标签，Space 有“文件”筛选，但没有实际文件内容。
- **修改方案**：增加文件列表/详情，展示文件名、类型、大小、发送者、发送时间、来源消息和处理状态。
- **验收条件**：文件来源明确是 Chat 自动索引，而不是独立网盘上传首页。

#### FILE-02 缺少文件操作与状态

- **优先级**：P0-阻断
- **修改方案**：覆盖打开、下载到本机、分享到当前 Chat、置顶、归档、搜索、关联到其他 Item；增加处理中、失败、不可用和重试状态。
- **验收条件**：“从 Space 隐藏”只归档索引，不删除 Chat 附件。

#### FILE-03 缺少删除文件资产的影响确认

- **优先级**：P0-阻断
- **修改方案**：文件删除前列出所有受影响入口：Chat 消息、Space 文件索引、关联待办/笔记/约定；明确删除的是底层加密资产，完成后二次入口均显示不可用。
- **验收条件**：不会将“隐藏索引”和“删除资产”设计成同一动作。

### 3.10 约定（Agreement）

PRD 依据：3.10、6.3、7.1、12.1–12.3。

#### AGR-01 当前确认状态存在语义冲突

- **优先级**：P0-阻断
- **现状**：详情页标记“待双方确认”，双方版本行却都出现绿色勾选，同时底部仍显示“确认约定”，可能被理解为双方已经确认。
- **修改方案**：清晰拆分：
  - 当前内容版本是否一致；
  - 我是否确认当前版本；
  - TA 是否确认当前版本；
  - 是否达到双方已确认。
  仅当两人的 confirmation 均绑定同一当前版本时，显示“双方已确认”。
- **验收条件**：任何单方确认状态都不能显示双方确认完成的图标或文案。

#### AGR-02 缺少 Draft 和“发起确认”阶段

- **优先级**：P0-阻断
- **修改方案**：新增约定草稿编辑页；“保存草稿”与“发起确认”分开；发起确认时显示将被冻结的版本号和内容预览。
- **验收条件**：保存草稿不代表本人或对方已经同意。

#### AGR-03 缺少“请求修改”流程

- **优先级**：P0-阻断
- **修改方案**：等待确认页增加“请求修改”，允许填写简短原因；提交后状态变为 Changes requested，并提供“一键回到 Chat 讨论”。
- **验收条件**：请求修改产生 Activity 和 Chat 系统事件，但不创建独立评论区。

#### AGR-04 缺少双方确认完成态与确认时间

- **优先级**：P0-阻断
- **修改方案**：增加 Confirmed 页面/卡片，显示当前版本、双方身份及各自确认时间；明确这是应用内确认，不是法定电子签名、公证或证据保全。
- **验收条件**：完成态和 Pending 状态视觉与文案明显不同。

#### AGR-05 缺少已确认内容修改后的重新确认

- **优先级**：P0-阻断
- **修改方案**：编辑已确认内容前提示将生成新版本；保存后旧版本快照继续可查，新版本的旧确认立即失效并重新进入 Pending。
- **验收条件**：不能覆盖旧版本，也不能沿用旧版本的确认状态。

#### AGR-06 缺少离线确认的版本冲突

- **优先级**：P0-阻断
- **修改方案**：增加“你确认的版本已不是最新版本”错误页，展示本地版本与当前版本，要求重新查看内容后确认。
- **验收条件**：离线确认永远不能绑定到错误的当前内容版本。

### 3.11 Activity、时间视图与搜索

PRD 依据：3.11–3.13、7.1、12.1–12.2。

#### AUX-01 Activity 事件类型覆盖不足

- **优先级**：P0-重要
- **现状**：已有 Activity 页面，但主要是约定、笔记和待办示例。
- **修改方案**：增加类型转换、归档/恢复/删除、Waiting、文件发送/删除、置顶/取消置顶等样例；为连续编辑提供“合并展示”样例。
- **验收条件**：Activity 为只读派生事件，界面没有手工创建或编辑入口，也不暗示法律审计完整性。

#### AUX-02 搜索只展示消息结果

- **优先级**：P0-阻断
- **现状**：有“消息/Space/文件”切换，但仅绘制消息结果。
- **修改方案**：补充：
  - Space 结果及类型筛选；
  - 文件名结果；
  - 结果来源标签；
  - 点击消息定位原 Chat；
  - 点击 Item 进入详情；
  - 空结果、索引重建、搜索失败状态。
- **验收条件**：同一文件的 Chat 视图与 Space 视图不会被误认为两份不同资产。

#### AUX-03 焚毁和已删除内容的搜索状态缺失

- **优先级**：P0-重要
- **修改方案**：设计焚毁消息不进入索引；销毁后从结果移除；来源失效的 Item 仍可被搜索，但来源显示不可用。
- **验收条件**：不会在搜索结果中泄露已经销毁的内容摘要。

### 3.12 设置、隐私与控制

PRD 依据：3.14–3.15、5.2、7.1、8.1–8.5、12.4。

#### SET-01 设置只有目录，没有子页

- **优先级**：P0-阻断
- **现状**：已有“身份与恢复码、关系与安全号码、设备管理、隐私与通知、存储与导出、解绑伴侣、删除账户”入口，但均未展开。
- **修改方案**：至少为上述每个入口补充主页面和关键确认/错误状态，不能仅以一张设置目录页交付开发。
- **验收条件**：每个入口的字段、默认值、影响范围和不可逆操作均有明确设计。

#### SET-02 缺少后台遮罩和任务切换器状态

- **优先级**：P0-阻断
- **修改方案**：补充 App 进入后台、任务切换器预览、重新进入要求解锁、后台 N 分钟清除解密内容后的状态稿。
- **验收条件**：任务切换器和锁屏页面不显示 Chat、Space 或搜索内容。

#### SET-03 缺少截屏、录屏和水印的能力边界

- **优先级**：P0-重要
- **修改方案**：在隐私设置中按平台说明 Android 安全窗口、iOS 录屏/投屏遮罩和截图后告警能力；可选水印展示截断 ID 与时间；明确无法阻止外部相机。
- **验收条件**：不使用“绝对防截屏”或“必然通知对方”等承诺。

#### SET-04 缺少通知隐私设置

- **优先级**：P0-阻断
- **修改方案**：提供默认“仅显示 M2Y 有一项更新”，以及用户主动开启本地解密预览的选项；待办/约定提醒说明由授权设备本地调度；在线和输入状态也在此控制。
- **验收条件**：默认推送不展示消息、标题、文件名或 Item 正文。

#### SET-05 缺少存储与导出流程

- **优先级**：P0-阻断
- **修改方案**：增加存储用量、加密导出、明文导出风险确认、应用解锁/二次确认、分享完成后临时文件清理说明。
- **验收条件**：导出行为的范围、风险和本地安全记录清晰。

#### SET-06 删除账户与共享内容删除没有区分

- **优先级**：P0-阻断
- **修改方案**：删除账户页逐级说明：本机数据、共享 Item、底层文件资产、关系路由、服务端密文和对方已有副本；避免与解绑、删除单个 Item 共用模糊弹窗。
- **验收条件**：用户不会把“删除账户”误解为能远程擦除对方已导出或离线复制的数据。

### 3.13 离线、同步、错误和恢复状态

PRD 依据：4.5、8.4、12.3。

#### SYNC-01 缺少全局离线状态

- **优先级**：P0-阻断
- **修改方案**：在 Chat/Space 顶部增加不遮挡内容的离线提示；允许浏览本地内容、创建/编辑 Item 和发送待处理消息；清楚标记“仅保存在本机，等待同步”。
- **验收条件**：离线不是空白错误页，也不会误报为已送达或已同步。

#### SYNC-02 缺少等待同步、已同步、同步失败

- **优先级**：P0-阻断
- **修改方案**：统一定义消息和 Item 的同步状态组件及重试入口；Chat、笔记、约定、文件上传复用同一语义。
- **验收条件**：状态有文字/图标，失败可恢复，重复重试不会在视觉上产生重复 Item 或 Activity。

#### SYNC-03 缺少冲突处理

- **优先级**：P0-阻断
- **修改方案**：分别提供：
  - 笔记冲突副本与手动合并；
  - Agreement 版本冲突与重新确认；
  - 结构化字段冲突后的最新状态和 Activity 说明；
  - 删除/归档/恢复正在同步时的操作限制。
- **验收条件**：没有任何“静默覆盖”或“错误版本被确认”的路径。

#### SYNC-04 缺少通用加载、错误和权限拒绝状态

- **优先级**：P0-重要
- **修改方案**：建立状态组件清单：首屏加载、局部加载、空状态、网络错误、解密失败、内容不可用、相机权限拒绝、通知权限拒绝、存储空间不足、文件过大、文件类型不支持。
- **验收条件**：每种错误均有明确下一步，不使用不可操作的泛化“出错了”。

### 3.14 文案、安全边界与无障碍

PRD 依据：1.8、3.1、3.10.4、3.14–3.15、8.5、11.1、12.4。

#### COPY-01 “匿名配对”属于过度承诺

- **优先级**：P0-阻断
- **现状**：欢迎页使用“不强制手机号，匿名配对”。
- **问题**：PRD 只允许说明 M2Y-ID 降低与现实身份的直接关联，不能承诺网络层完全匿名。
- **修改方案**：改为：

  > “无需手机号或邮箱，使用随机 M2Y-ID 配对。”

  可在说明页补充“服务运行仍可能处理必要的网络与风控元数据”。
- **验收条件**：全稿不出现“完全匿名、绝对无痕、零元数据”等不可验证承诺。

#### COPY-02 删除文案“永久移除且无法恢复”不符合生命周期规则

- **优先级**：P0-阻断
- **修改方案**：普通 Shared Item 改为“删除后将在短暂撤销期结束后清理”；底层文件资产删除单独提示不可恢复及影响入口；同时声明外部副本不受控制。
- **验收条件**：文案与具体对象的删除语义一致。

#### COPY-03 Agreement 缺少法律边界说明

- **优先级**：P0-重要
- **修改方案**：在首次发起确认及 Agreement 帮助说明中增加：这是应用内双方对同一内容版本的确认，不等同于电子签名、公证、可信时间戳或证据保全。
- **验收条件**：任何页面不使用“签署、存证、不可篡改、可作证”等超出 PRD 的营销表达。

#### A11Y-01 状态表达仍有仅靠颜色或英文短标签的风险

- **优先级**：P0-重要
- **现状**：部分状态以紫/绿/灰圆点和英文 Waiting 表达，动态字体下存在裁切。
- **修改方案**：所有状态采用文字+图标；定义正常、警告、失败和危险颜色的对比度；为 VoiceOver/TalkBack 指定可读标签和顺序。
- **验收条件**：去色后仍能理解状态，屏幕阅读器可完整读出对象、状态和主操作。

#### A11Y-02 缺少动态字体和多设备尺寸稿

- **优先级**：P0-规范
- **现状**：当前主要为 390×844 单一尺寸。
- **修改方案**：至少补充：
  - 小屏 Android；
  - 典型 Android 设备；
  - iOS 大号动态字体；
  - 键盘弹出；
  - 长中文标题、长文件名和长安全提示；
  - 底部安全区变化。
- **验收条件**：不截断主操作、状态和不可逆风险说明；触控目标满足平台最低尺寸。

## 4. 静态设计稿无法证明的 PRD 要求

以下项目不能仅靠 SVG 判断满足。设计团队需要补充交互规范、数据/状态说明，研发与安全团队还需提供实现与测试证据。

| 需求 | 当前问题 | 需要补充的交付物 | 验证方式 |
|---|---|---|---|
| 端到端加密 | 锁图标与文案不能证明真实 E2EE | 安全架构、密钥生命周期、威胁模型 | 安全评审、渗透测试、协议测试 |
| 服务端零明文 | 欢迎页文案不能证明数据库/队列/日志无明文 | 数据流图、字段分级、日志规范 | 服务端与日志抽检 |
| 密钥安全存储 | 无法从 UI 判断 | iOS Keychain/Android Keystore 方案 | 真机与安全测试 |
| 密文同步与幂等 | 无同步状态模型 | 消息、Item、Activity 操作状态机 | 离线/重试/重复投递测试 |
| 推送默认无明文 | 设置子页缺失 | 通知事件与预览策略表 | 锁屏与推送真机测试 |
| 本地搜索隐私 | 搜索页不能证明查询词不上云 | 搜索架构与索引清理规则 | 网络抓包、销毁残留测试 |
| 焚毁无残留 | 没有焚毁状态稿和清理规范 | 数据库、缓存、缩略图、索引清理矩阵 | 取证式残留测试 |
| 后台遮罩 | 无后台/任务切换稿 | 平台行为说明与状态稿 | iOS/Android 真机验证 |
| 性能目标 | 静态稿无法证明 P95 | 骨架屏/渐进加载规范、性能预算 | 1 万消息/1 千 Item 压测 |
| 无障碍 | SVG 无语义树 | 组件语义、焦点顺序、动态字体规范 | VoiceOver/TalkBack 验收 |

## 7. 设计交付验收清单

设计稿整改完成后，应使用以下清单进行冻结前验收。

### 7.1 核心体验

- [ ] 可从全新安装完成身份创建、恢复材料保存、应用锁设置、配对和首条消息；
- [ ] 三种配对方式均可完成双方确认与安全号码核验；
- [ ] 单条和多条常规消息可在 3 次操作内保存到 Space；
- [ ] 收藏、待办、笔记、文件、约定均可从 Chat 到 Space，再回到 Chat；
- [ ] Item 可查看原始聊天或明确显示来源不可用；
- [ ] “在聊天中讨论”不会创建独立评论区；
- [ ] Space Home 正确表达需要你、接下来、置顶、最近更新；
- [ ] 类型筛选仍是同一 Shared Item 集合，而不是五套工具。

### 7.2 状态正确性

- [ ] Task Waiting 必须选择正在等谁；
- [ ] 只有被等待的一方在“需要你”看到该 Task；
- [ ] Agreement 单方确认时绝不显示“双方已确认”；
- [ ] 双方确认必须绑定同一版本；
- [ ] 修改已确认约定后生成新版本并使旧确认失效；
- [ ] Activity 能合并短时间连续编辑；
- [ ] 文件在 Chat 与 Space 明确引用同一资产；
- [ ] 删除文件前列出全部受影响入口。

### 7.3 离线与错误恢复

- [ ] 离线时仍能浏览本地内容并创建待同步操作；
- [ ] 等待同步、已同步和失败状态可区分；
- [ ] 重试不会在界面上产生重复消息、Item、Activity 或确认；
- [ ] 笔记冲突保留双方完整版本；
- [ ] Agreement 版本变化后要求重新查看和确认；
- [ ] 删除、归档和恢复具有同步中及失败恢复状态。

### 7.4 安全与隐私

- [ ] 焚毁消息没有 Save to Space 入口；
- [ ] 焚毁模式与常规模式对双方清晰可见；
- [ ] 锁屏、后台和任务切换器设计不泄露内容；
- [ ] 推送默认文案不包含内容明文；
- [ ] 新设备、密钥变化和安全号码变化对双方可见；
- [ ] 删除、解绑、设备撤销和导出的影响与限制准确；
- [ ] 不出现完全匿名、绝对防截屏、远程必然擦除、零元数据或法律存证等过度承诺。

### 7.5 可用性与无障碍

- [ ] 状态同时使用文字和图标，不仅依赖颜色；
- [ ] 关键按钮和危险操作可被屏幕阅读器正确识别；
- [ ] 动态字体下无核心信息和按钮裁切；
- [ ] 小屏 Android、典型 iOS、键盘弹出和长文本状态均有验证；
- [ ] 删除、解绑、文件资产删除等不可逆操作明确说明影响范围。

## 8. 最终判定标准

只有同时满足以下条件，设计稿才能判定为“满足 PRD P0/MVP”：

1. 本文 P0-阻断项均已关闭；
2. PRD 第 12 节每一项均能映射到具体页面、组件状态或配套规范；
3. 五类 Shared Item 均形成 Chat → Space → Chat 的闭环；
4. 离线、同步、冲突和安全异常不再依赖开发自行补全交互；
5. 所有安全与隐私文案均经过研发和安全团队确认可实现；
6. 设计稿附带页面流程图、对象状态表、错误状态表和无障碍标注。

在上述条件完成前，建议设计评审结论保持为：

> **方向通过，P0/MVP 设计覆盖不通过，需按本报告补齐后复审。**
