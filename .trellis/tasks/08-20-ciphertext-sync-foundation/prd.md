# 密文同步与离线冲突基础

## Goal

在生产身份与配对边界之上，实现服务端不可解密的最小密文同步闭环，为 Chat 与 Space 的真实双端状态提供 transport、outbox/inbox、重试和冲突基础。

## Requirements

- 服务端、推送、日志和分析不得接触消息明文、附件明文或会话密钥。
- 建立版本化 envelope、幂等 ID、outbox/inbox 和明确 ACK/重试语义。
- 覆盖离线、重复、乱序、进程重启、超时和最小冲突处理。
- UI 只有在协议证据支持时才能展示发送、送达、等待同步或失败状态。
- 富消息与完整文件体验由后续子任务负责。

## Acceptance Criteria

- [ ] 两端文本消息可在线和离线重连后保持一致。
- [ ] 重复、乱序和重启不会静默丢失或重复应用消息。
- [ ] 有可审计证据证明服务端与日志不可见明文和密钥。
- [ ] 任务归档时更新父任务完成度和声明边界。

## Dependency

- 在生产身份、配对和安全号码子任务通过后启动。
