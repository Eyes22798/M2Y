# m2y-crypto

Android-only Expo local module for the M0 libsignal integration spike.

- The module pins the official `org.signal:libsignal-client` and
  `org.signal:libsignal-android` artifacts to `0.101.0`.
- JavaScript receives only redacted capability/results contracts. Private keys,
  protocol records, plaintext, fingerprints, and native exception details must
  remain inside the native boundary.
- `getSpikeInfo` is the Gate 1 native-load probe. The development-only
  acceptance commands then run fresh PQXDH, encrypted checkpoint creation,
  process-restart resume, fail-closed negative cases, aggregate performance,
  and explicit cleanup.
- The checkpoint is a strict versioned snapshot encrypted with an Android
  Keystore AES-256-GCM key and replaced through `AtomicFile`. Protocol actions
  mutate a native working copy and publish only after the encrypted checkpoint
  commit succeeds.
- The performance probe wraps a synthetic 32-byte attachment content key with
  the established session and streams a separate synthetic 100 MB temporary
  file. It is not a production attachment encryption format.
- Android packaging rules are applied through `app.plugin.js`, because `android/`
  is generated by Expo CNG and is not a source-of-truth directory.
- Android compilation uses a JDK 21 toolchain while emitting JVM 17 bytecode;
  the consuming app enables the exact core-library desugaring dependency declared
  by the official libsignal AAR metadata.

libsignal is AGPL-3.0-only. See the repository `THIRD_PARTY_NOTICES.md` and the
active Trellis task for the release obligations and current go/no-go evidence.
Passing this isolated harness does not claim that production E2EE, pairing,
persistence, sync, recovery, or multi-device support is implemented.
